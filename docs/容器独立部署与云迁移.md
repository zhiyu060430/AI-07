# 源码一条命令启动与云迁移

暂时用自己的电脑给跨网络团队共享平台，见[本机跨网络团队访问](本机跨网络团队访问.md)。该模式通过一个HTTPS入口共享现有数据，Worker和数据库仍在本机Docker内部。

此文对应 `compose.portable.yaml`、根目录 `start.ps1` / `start.sh`。它是新的独立部署入口，不与旧 `compose.yaml` / `compose.platform.yaml` 混用。运行数据全部在 Docker 命名卷中，运行服务没有项目目录挂载，没有 Docker socket。源码只用于构建镜像。

## 首次启动

Windows（PowerShell，在源码根目录）：

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1 -InstallDocker
```

已安装 Docker 时省略 `-InstallDocker`。该参数在缺少 Docker 时通过 winget 安装官方 Docker Desktop；首次启用虚拟化/WSL2可能需要重启 Windows，再执行同一命令，脚本不能绕过系统重启。无需本机 Python、Node.js、npm、uv、PostgreSQL、FDS 或 Blender。

Ubuntu / Debian 云服务器（取得源码后）：

```sh
sudo sh start.sh --install-docker
```

其他系统需先安装 Docker Engine/Desktop 和 Compose v2，再 `sh start.sh`。当前引擎二进制为 Linux x86_64，部署目标使用 amd64；ARM 机器尚未验证。宿主 Docker 支持 Compose `gpus` 字段时要求 Compose ≥2.30。

默认启动完整 CPU 工作台：PostgreSQL、API、Web、Label Studio、Worker，自动下载校验 FDS 6.11.1 和 Blender 4.5.3，构建三维编辑器和内置简模。浏览器打开 http://localhost:3000。CPU 模式可仿真、渲染、预览和审核，不提供 GPU 扩散增强/训练；未准备的 GPU 任务会失败，不伪造结果。

需要扩散增强、FID和检测训练时，在兼容 NVIDIA 硬件/驱动及容器 GPU 支持就绪后执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1 -Gpu
```

```sh
sudo sh start.sh --gpu
```

此模式持久保存到凭据卷，后续普通启动继续使用 GPU Worker。自动构建 PyTorch 2.7.1 / CUDA 12.8 镜像，下载固定修订的 SD1.5、YOLO11n、FID 权重，并复用原下载脚本的 SHA256 校验。首次下载耗时、空间取决于网络和镜像缓存；需要数 GB 权重及更大的镜像/运行缓存空间。ControlNet 权重及原项目未实现的算法功能不会由部署脚本补齐。

Python 3.12、GPU基础镜像、Node 24、Nginx 1.28及PostgreSQL 16备份工具镜像固定digest；数据库PostgreSQL 16和Label Studio 1.22.0以镜像标签声明，前端 npm ci 使用锁文件。系统apt包及部分Python依赖仍按版本范围解析，不能称所有系统包逐字节复现。具体 Python 依赖沿用现有 requirements 文件。

仅预下载/构建不启动：Windows `-Action Setup`，Linux `--action setup`；可同时传 `-Gpu` / `--gpu`。

环境准备完整后，日常启动直接复用本地镜像，不执行构建或访问镜像仓库。更新源码后显式重建：Windows追加 `-Rebuild`，Linux追加 `--rebuild`；首次启动、缺失镜像/模型或切换GPU模式时自动准备。`-Action Setup` / `--action setup` 也会主动构建。

如果看到 `failed to resolve source metadata`、`registry-1.docker.io` 和 `EOF`，表示Docker连接镜像仓库中断，不是平台账户或数据库错误。脚本会对网络下载/构建故障有限重试；持续失败时需要检查Docker Desktop/Engine的网络或代理，再运行同一命令。已有完整环境的日常启动不依赖Docker Hub。不要为此删除数据库卷。

## 用户名和密码

首次访问，自行填写用户名和密码，首次账户自动成为管理员（角色名“架构师”）。用户名3–32位字母、数字、下划线或短横线；密码10–256位。密码保存 PBKDF2-SHA256 加盐哈希，不保存明文，没有默认管理员密码。后续人员由管理员在左侧“项目成员”中创建并分配角色；独立部署关闭后续公开自助注册。旧部署的注册策略保持兼容。

数据库、Label Studio服务凭据自动随机生成，保存在 `ai07-portable_credentials` 卷；工作进程密钥在 `ai07-portable_platform-state` 卷。网页平台账户与数据库服务账户不同。完整 Label Studio 的服务用户名仍为 `ai07-service@localhost`，主要使用平台内嵌审核，服务密码不要分发给普通用户。

## 存储位置与停止

默认 Compose 项目名 `ai07-portable`，持久卷包括：

- `postgres`：业务数据库，包括账户、任务、版本索引。
- `artifacts`：上传、生成图像、视频、仿真/渲染缓存、标签、导出和模型运行缓存。
- `platform-state`：Worker密钥、DVC仓库与版本备份。
- `models`：下载的权重。
- `label-studio`：标注服务数据库和配置。
- `credentials`：服务凭据及部署设置。
- `backups`：整栈迁移归档及校验文件。

卷的真实名称为 `<项目名>_<卷名>`。FDS、Blender、Python、Node和系统依赖在镜像/构建缓存中。全部由 Docker 管理，仍占 Docker 所在机器的物理存储；本机 Docker 不可能仅因为改成卷就零本机占用。没有对 `D:` 盘或某个用户名的运行依赖。

停止：`powershell -File .\start.ps1 -Action Stop` 或 `sh start.sh --action stop`。停止保留卷；不要执行 `down -v` 或删除卷。源码删除、容器重建都不会自动删除命名卷，但卸载 Docker 时删除数据会丢失它们。

## 备份和恢复

备份前请完成或取消运行中的作业；停止Worker会中断尚未完成的任务。备份会暂停 Web/API/Worker/Label Studio以避免数据库与文件处于不同时间点，PostgreSQL保持运行并使用同主版本pg_dump导出；结束后恢复服务。归档包含全部上述业务数据、权重和凭据，保存在 Docker `backups` 卷，附 SHA256。

```powershell
powershell -File .\start.ps1 -Action Backup -Backup migrate.tar
powershell -File .\start.ps1 -Action ListBackups
# 仅在你明确需要本地文件时导出；这是主动复制，会额外占磁盘空间
powershell -File .\start.ps1 -Action Export -Backup migrate.tar -Path E:\ai07-transfer
```

```sh
sudo sh start.sh --action backup --backup migrate.tar
sudo sh start.sh --action list-backups
sudo sh start.sh --action export --backup migrate.tar --path /mnt/transfer
```

恢复会覆盖目标项目数据，执行前先备份目标。先将 tar 与 `.tar.sha256` 放到服务器同一目录，运行初始化/启动构建镜像，再导入、恢复：

```sh
sudo sh start.sh --install-docker
sudo sh start.sh --action import --backup migrate.tar --path /mnt/transfer/migrate.tar
sudo sh start.sh --action restore --backup migrate.tar
```

Windows对应 `-Action Import -Backup migrate.tar -Path E:\ai07-transfer\migrate.tar` 和 `-Action Restore -Backup migrate.tar`。恢复保留目标数据库服务密码和目标端口/GPU/访问域名设置，恢复原平台账户、标注令牌和数据，原用户名密码继续有效。归档含敏感数据，只给有权限的人。恢复中断时保持停止并重试恢复，勿将不完整恢复当成功。

## Google Drive 能做什么

可以作为整栈归档、导出数据集或模型的远程备份目的地。它不是运行 Docker 的服务器，也不是 PostgreSQL 所需的块设备/完整本地文件系统，不能把本项目整个 Docker 数据目录或正在写入的数据库直接放入“我的云端硬盘”并承诺可靠且不占本地空间。挂载云盘通常还会使用本地缓存。

不想在本机中转归档，可在 Docker 中使用 rclone，将 `backups` 卷中的归档直接上传 Google Drive；需你本人完成 Google 授权，不是粘贴“我的云端硬盘”链接就可访问。卷仍依赖Docker主机磁盘，见[Docker存储文档](https://docs.docker.com/engine/storage/volumes/)；挂载缓存限制见[rclone VFS说明](https://rclone.org/commands/rclone_mount/#vfs-file-caching)。以下是后续手动配置和上传步骤，本次不会自动授权或上传：

```sh
docker run --rm -it -v ai07-gdrive-config:/config/rclone rclone/rclone:1.69 config
# 将 remote 命名为 gdrive，选择 Google Drive，按提示完成本人 OAuth
docker run --rm -v ai07-gdrive-config:/config/rclone -v ai07-portable_backups:/data:ro rclone/rclone:1.69 copy /data gdrive:AI07-backups --include 'migrate.tar*' --checksum
```

容器内没有浏览器时，自动浏览器授权选 `n`，按终端提示在有浏览器的机器上完成授权，再把授权结果粘贴回终端；不要公开token。具体步骤见[rclone远程授权](https://rclone.org/remote_setup/)。

下载到云服务器的 Docker 卷，无需落入本地电脑文件夹：

```sh
# 云服务器先单独完成自己的 rclone OAuth配置，不共享公开链接或暴露 token
docker run --rm -it -v ai07-gdrive-config:/config/rclone rclone/rclone:1.69 config
docker run --rm -v ai07-gdrive-config:/config/rclone -v ai07-portable_backups:/data rclone/rclone:1.69 copy gdrive:AI07-backups /data --include 'migrate.tar*' --checksum
sudo sh start.sh --action restore --backup migrate.tar
```

备份归档在生成时仍占源机器 Docker 磁盘，下载后也占服务器磁盘。真正让运行数据不占个人电脑存储的方法：把 Docker 和 Worker部署在云服务器，电脑只打开浏览器（仍有少量浏览器缓存）。服务器照常需要CPU/内存/磁盘，GPU任务还需要兼容GPU资源。

## 云服务器访问

默认只绑定服务器回环地址，不会直接开放公网。在电脑使用 SSH 隧道即可先安全访问，避免未配置域名/TLS时开放管理员初始化页：

```sh
ssh -L 3000:127.0.0.1:3000 -L 8082:127.0.0.1:8082 user@your-server
```

然后在电脑打开 http://localhost:3000。公开域名部署时，在服务器配置HTTPS反向代理，把请求转发到127.0.0.1:3000；首次启动前先通过隧道创建管理员。设置环境 `AI07_ALLOWED_ORIGINS=https://你的域名`、`AI07_SECURE_COOKIE=1` 后执行启动脚本，设置会保存到凭据卷。TLS、DNS、云主机和Google授权需你提供实际资源；源码容器改造不等于已经部署到你的云账户。

端口冲突可指定 `-Port 13000 -ApiPort 18092 -LabelPort 18082` 或 `--port 13000 --api-port 18092 --label-port 18082`。隔离新项目用 `-Project ai07-test` / `--project ai07-test`，对应独立卷，避免误认为旧数据丢失。

旧版项目的数据不会随普通启动自动复制：为避免把私人旧数据带给源码接收者，新机器默认初始化空数据库。当前Windows旧部署可以在任务全部完成/取消后执行显式迁移：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/migrate-legacy.ps1
# 本机已有兼容NVIDIA环境，需要继续使用GPU增强时加 -Gpu
```

它先准备新镜像，再停止旧工作进程/API/标注写入，读取旧数据库及文件生成完整备份至新Docker卷，启动新栈并恢复。旧文件和旧数据库卷保留，不执行删除；新平台原用户名密码保持有效。该操作需要额外空间保存归档与新数据副本；失败时原始数据仍在，按错误提示恢复旧入口。只有确认新平台与云端恢复成功后，才另行清理旧数据。若使用自定义旧Compose项目名或端口，传 `-LegacyProject` / `-LegacyApiPort`；迁移目标必须是尚无需要保留数据的新项目。

原 `scripts/start-platform.ps1` 默认转到新入口；显式 `-Legacy` 才会启动旧宿主Worker部署。旧独立FirePhantom、8080标注服务及其Docker卷保留；它们不是新主平台的运行依赖，需要继续独立使用时应另外备份/迁移其卷及数据库。

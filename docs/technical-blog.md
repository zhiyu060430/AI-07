# 从火焰物理场到可复现数据集

火焰数据集仿体系统把一次生成请求固定成一条可审计链：基础场景生成 Blender 脚本并烘焙一团会动的火。Blender 没有产出画面时才使用参数化羽流，结果明确记录来源。温度、烟和速度网格来自这套羽流。

Stable Diffusion 不负责生成火焰本身。它对每个环境、天气、视角组合做一次 img2img，初始图是引擎第 0 帧，后面的帧跟着仿真里的火焰位移。扩散失败时视频就是引擎原片。质量模块遵循 FID 距离、IS 和 SSIM 的定义，真实 Inception 权重和参考集必须通过环境变量显式注入。

标注结果以 Label Studio task 为主格式，并从同一个对象列表导出 COCO、Pascal VOC 和 YOLO，避免三套坐标逻辑漂移。DatasetStore 将 payload 交给本地 DVC 内容寻址缓存，版本元数据先脱敏，配置 Fernet key 后再写入工作区和快照。版本 API 支持查询、文件读取、归档下载和回滚。账号、作业进度、版本目录和样本索引存在 PostgreSQL，服务重启后可恢复排队任务；文件和 DVC 缓存仍在磁盘上。人只登录工作台，打开 Label Studio 时不再输入第二套密码。

验收时要把系统能力和真实指标分开。自动化测试验证接口、格式、幂等性、异常路径和覆盖率；现场环境还必须用真实 Blender、Inception 权重、火焰参考集、Label Studio 复核集和下游检测基准测量 SRS 要求的 5%、80%、85% 和 15% 数字。
